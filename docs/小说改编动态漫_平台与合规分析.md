# 小说改编动态漫：平台、合规与落地路径分析

> 日期：2026-11-28
> 性质：可行性研究与决策备忘，**不是法律意见**；平台政策与备案口径变动快，正式立项前须以官方公告/合同为准。
> 来源标注：【官方】= 平台/法院/监管公开信息；【行业】= 行业媒体或从业者口径；【待核实】= 需向平台或律师确认。

---

## 0. 结论摘要

1. **想法成立，但顺序要反过来**：真正的门槛不是「AI 能不能生成」，而是「版权和资质能不能过」。技术侧 ImageHub 已有明显成本优势，应把精力先花在前两步。
2. **两条完全不同的生意**：
   - **红果**：番茄 IP + 竖屏 1–2 分钟 × 80–100 集，流量生意，短期现金流，但同质化、审核严、分成系数在降。
   - **B 站**：原创/公版 IP + 横屏 3 分钟+ × 3 集起，IP 生意，变现慢，但粉丝和 IP 是自己的；个人可直接投稿，不强制机构。
3. **已选方向**：B 站原创横屏精品管线。
4. **「3 本小说改编成 1 本」只能停在母题层**：A 世界观 + B 人设 + C 桥段的拼法，取的是三本书的「表达」，三个权利人可以分别主张；AI 重写不改变侵权定性。
5. **推荐路径**：公版 / 自写 / 授权三选一 → 3–6 集样片验证 → 数据达标后再谈量产与授权 IP。

## 2. 版权：本项目最大的风险

### 2.1 番茄 IP 的授权边界

- 番茄 IP 库官方口径：授权成品「通过短剧版权中心上线至集团多渠道分发，**包括抖音、红果等**」。
- **B 站不在该分发范围**。把番茄 IP 改编后发 B 站，大概率违反授权。
- 番茄 IP 库明确**不可改编类型**：动态解说漫剧（含 AI 仿真人解说）、静态解说漫剧、AIGC 推书视频【行业】。
- 有从业者反馈番茄 IP 改编合作已严控/暂停新增，且要求平台首发、月产达标、断更赔付【待核实】。

**结论**：要做 B 站原创精品，IP 来源只能是：自写、公版、或单独取得授权。

### 2.2 「A 世界观 + B 人设 + C 桥段」的法律定性

法院判断改编侵权，不是看文字重复率，而是「抽象—过滤—比较」：

1. **抽象**：把思想从表达中剥离；
2. **过滤**：剔除公有领域和表达方式有限的部分；
3. **比较**：看被诉作品是否使用了原作**具有独创性的表达**——重点是主线剧情背景设计、人物关系、故事情节推进等「关键内核」及其具体表达。

逐项拆解：

| 元素 | 安全（思想/通用） | 危险（表达） |
|---|---|---|
| A 世界观 | 修仙、系统、赛博、克苏鲁氛围等通用母题 | 具体力量体系、规则、专有名词、组织架构 |
| B 人设 | 冷酷男主、元气女主等原型 | 高度具体的人物群像、关系网、成长弧线、标志性外形 |
| C 桥段 | 退婚、英雄救美、扮猪吃虎等通用桥段 | 具体情节序列、触发方式、顺序、冲突解决设计、名场面 |

**三本各取一块 = 三个权利人可分别主张，合并不会稀释，反而增加被告数量。**

### 2.3 为什么「AI 再写一遍」不洗版权

- **最高法《关于依法审理涉人工智能纠纷案件的意见》（法发〔2026〕10 号，2026-09-07）第 12 条**【官方】：
  > 人工智能使用者知道或者应当知道在先作品存在，利用人工智能生成与在先作品实质相似的作品且无合理抗辩理由，在先作品权利人请求其承担侵权责任的，人民法院应予支持。
- **天津和平区首例「小说喂 AI 做漫剧」案（2026-09）**【官方/行业】：被告将原告完整文字作品导入 AI 生成漫剧并公开传播，法院认定侵害**改编权 + 信息网络传播权**，调解赔偿；「AI 生成」不是免责理由。
- 法院会穿透「提示词—生成—筛选」的形式，追问独创性内核是否被迁移；表层措辞改写不能切断改编关系。
- 「知道或应当知道」在主动选书、主动导入的场景下几乎必然成立。
- AI 输出带隐形水印/可溯源；平台还有「剧情截取不超过原著 10%」的规则——**有授权也不能整本搬，没授权更不能靠只截一点规避**【行业】。
- 平台下架力度：红果 2026 年一季度下架违规漫剧 1718 部，4 月 7 日起一周拦截处罚 3522 部，6 月单月 14357 部【行业】。

### 2.4 安全线

安全的不是「改多少字」，而是**只取思想，不取表达**：

- **可以借**：类型、题材、情绪曲线、爽点节奏、「读者为什么爱看」；
- **不能借**：具体人物关系、独特设定细节、情节序列、名场面、标志性台词；
- **独立性检验**：把人物换名、情节顺序打乱后，普通读者还能不能认出「这是某本书」？能认出，就是实质性相似；
- **过程留痕**：保留原创大纲、版本、时间戳；提示词记录既是权利证据，也可能成为侵权证据。

### 2.5 公版的坑

- 原著公版，不代表**现代演绎版本**公版：某版动画/漫画/影视的人物造型、标志性台词、美术风格仍可能受著作权保护；
- 公版改编也要注意平台「魔改经典」审核口径与内容规范。

### 2.6 平台检测 ≠ 法律判定

- 平台文字查重可能查不出改写后的文本，但剧情/人设比对、人工审核、原作者投诉都能触发；
- 后果：下架、扣分/封号、赔偿；以营利为目的且情节严重，可能触及《刑法》第 217 条侵犯著作权罪；
- **「检测不到」不等于「合法」。**

## 4. 技术路线与管线

### 4.1 ImageHub 现有能力

- 文生图：Qwen-Image-2.1-Turbo、Z-Image-Turbo、MOSS-Image-SFT、FLUX.2 Klein 4B、Nemotron-30B-A3B；
- 图片编辑：Qwen-Image-Edit-2511（可做角色参考、局部修改）；
- TTS：Qwen3-TTS 1.7B 三变体（CustomVoice / VoiceDesign / Base），支持音色设计与克隆；
- 后端：直连 diffusers 服务 + ComfyUI（ControlNet、视频工作流可扩展）；
- 硬件：2×RTX 3090（24GB）用于图像/TTS，GPU2/3 跑 vLLM 3.6 可承担拆书与分镜 LLM。

### 4.2 形态选择：动态漫 vs 真动态

| 形态 | 做法 | 成本 | 适用 |
|---|---|---|---|
| 动态漫（推荐主力） | 静态分镜图 + 分层运镜（推拉摇移/视差）+ 局部动效 + 配音 + 字幕 | 低，自家 GPU 边际≈电费 | 全片主体 |
| 真动态（点睛） | Wan2.2-TI2V-5B 图生视频，720p/5s | 4090 约 9 分钟/镜头，3090 更慢 | 每集 5–10 个关键镜头 |

- 不建议全片 i2v：一集 40–60 镜头会让单集 GPU 时间到数小时甚至一天，且一致性更难控。
- Wan2.2-TI2V-5B 单卡 24GB 可跑；需额外约 10GB 模型与 ComfyUI 原生工作流。

### 4.3 推荐管线

```
3 本小说（公版/自写/授权）
  → 母题提炼（只取类型、情绪、爽点）
  → 故事圣经（世界观/人物/主线/分集）
  → 分集大纲 → 分镜脚本（镜号/景别/台词/时长）
  → 角色圣经（设定图，全片参考）
  → 分镜出图（批量 + 人工筛选修图）
  → 关键镜头 i2v（Wan2.2）
  → 剪辑/音效/配乐/字幕
  → B 站投稿（AI 标识 + 备案）
```

### 4.4 角色一致性

- 先出「角色圣经」：正面/侧面/表情/服装/比例；
- 后续每张分镜以角色设定图 + Qwen-Image-Edit / 参考图条件化；
- 固定 seed、固定提示词模板、固定画风 LoRA（如需要）；
- 每集做一次一致性抽检，发现崩坏立即回炉。

### 4.5 质量标杆

- B 站 AI 动画《牌子》：7 分多钟，制作周期 23 天，上线一周播放 1000 万+，获 B 站首届 AI 创作大赛一等奖及 100 万元奖励【行业】。
- 结论：精品路线的胜负手是**剧本、分镜、演出、节奏**，不是模型；AI 只做产能。

### 4.7 总体技术架构

```
原著/母题（公版/自写/授权）
        │
        ▼
┌─────────────────────────────┐
│ LLM 层（vLLM 3.6，GPU2/3）   │
│ 母题提炼 / 故事圣经 / 分集   │
│ 分镜脚本 / 对白提取          │
└─────────────┬───────────────┘
              │ 结构化 JSON
              ▼
┌─────────────────────────────┐
│ ImageHub BFF（5569）         │
│ 项目/集/镜头状态机           │
│ 队列、重试、断点续跑         │
│ GPU 仲裁、图像/TTS 互斥      │
└───┬──────────┬──────────┬───┘
    │          │          │
    ▼          ▼          ▼
 图像模型   Qwen-Edit   Qwen3-TTS
（Qwen/Z/   （修图/     （配音/
 MOSS/     参考图）     克隆）
 FLUX/Nemotron）
    │          │          │
    └────┬─────┴────┬─────┘
         ▼          ▼
   ComfyUI（Wan2.2 i2v / 合成辅助）
         │
         ▼
   FFmpeg 合成（运镜/转场/字幕/混音）
         │
         ▼
   审片 → 合规检查 → B 站投稿包
```

设计原则：

1. **LLM 与图像 GPU 分离**：拆书、分镜、对白提取走 vLLM（GPU2/3），不占图像 GPU；
2. **复用现有互斥**：图像与 TTS 继续走 `_image_session` / `_tts_begin_request` 的仲裁队列；
3. **长任务可恢复**：每个镜头是独立状态机，失败只重跑该镜头，不重跑整集；
4. **人机分工**：AI 负责产能（出图、配音、合成），人负责故事、分镜、筛选、修图、剪辑。

### 4.9 数据模型（建议）

新增独立表，不改 `jobs`（漫剧与图库历史分离）：

| 表 | 关键字段 |
|---|---|
| `drama_projects` | id, title, ip_source, style, status, created |
| `drama_episodes` | id, project_id, no, title, duration, status |
| `drama_scenes` | id, episode_id, no, location, time, summary |
| `drama_shots` | id, scene_id, no, framing, camera_move, duration, prompt, dialogue, ref_assets, image, video, audio, subtitle, status |
| `drama_characters` | id, project_id, name, bible_assets, voice_id, prompt_token |
| `drama_assets` | id, project_id, type, path, version, created |
| `drama_renders` | id, shot_id, kind, params, output, status, error, elapsed |

约定：

- 所有生成物版本化，重生成不覆盖旧版，可回滚；
- `status` 统一状态机：`pending → queued → running → done / failed / skipped`；
- 项目目录：`projects/<project_id>/<episode>/<shot>/`，与 `output/` 分离；
- 导出包：`exports/<project_id>/<episode>.mp4` + 字幕 + 封面。

### 4.11 模型选型

注意：

- 3090（sm_86）不支持 convrot 量化（int8/w4a8），只能用 bf16/GGUF；
- 所有模型单边上限 2048，横屏 16:9 建议 1536×864 或 1920×1080 生成后放大；
- 图像与 TTS 严格互斥，批量任务要按队列串行，避免显存争抢。

### 4.12 角色一致性方案

1. **角色圣经**：每个主要角色 6–8 张（正面/侧面/背面/表情/服装/比例），人工选定「官方脸」；
2. **提示词 token**：固定角色描述块（发型、瞳色、脸型、服装、饰品），所有分镜复用；
3. **参考图条件化**：出图时附角色圣经图（Qwen-Edit / 参考图工作流），不让模型自由发挥；
4. **固定 seed 族**：同一角色同一场景用相近 seed，减少漂移；
5. **画风锚点**：固定画风 LoRA 或固定风格提示词，避免每集画风跳变；
6. **抽检**：每 10 个镜头做一次角色特征比对，发现崩坏立即用 Edit 局部修，不整张重生成；
7. **镜头规避**：大特写、复杂手部、多人同框容易崩，分镜阶段就尽量规避或用景别/遮挡处理。

### 4.13 动态漫技法

- **分层**：背景 / 中景 / 角色 / 前景 / 特效分层，便于独立运镜；
- **2.5D 相机**：推、拉、摇、移、升降 + 视差，单镜头 2–4 秒；
- **局部动效**：头发、衣摆、光斑、雨雪、粒子、镜头光晕，避免「整张图平移」的 PPT 感；
- **口型**：不做精细口型，用侧脸、背影、遮挡、切镜规避；必须特写时用 2–3 帧口型循环；
- **转场**：硬切为主，情绪节点用黑场/白闪/匹配剪辑；
- **节奏**：每 3–5 秒一个信息点；对话戏用正反打 + 反应镜头；
- **镜头语言**：建立镜头 → 中景叙事 → 特写情绪 → 动作镜头，避免全程中景。

### 4.14 关键镜头 i2v 策略

- 只做四类：开场建立镜头、高潮动作、情绪转折、结尾钩子；
- 每集 5–10 个，每个 2–5 秒，占全片 10%–20%；
- 用首帧 + 运动提示（推/拉/摇/人物动作），必要时首尾帧控制；
- 失败重试上限 2 次，仍崩坏则退回动态漫处理；
- 3090 实测速度待补（预计比 4090 慢 1.5–2 倍）。

### 4.15 音频与字幕

- TTS 24kHz 输出，统一重采样到 48kHz；
- 主角固定音色，旁白单独音色，配角按角色分配；
- 每句单独生成，保留时间戳，便于对齐字幕与剪辑；
- 人工调语速、停顿、重音；情绪不足的句子重生成或换音色；
- BGM/音效/字体必须商用授权，保留授权凭证；
- 字幕先机器对齐，再人工校对专有名词与断句。

### 4.16 合成与导出

- FFmpeg 合成：1920×1080、24fps、H.264、AAC 192k；
- 运镜用 `zoompan` / `crop` / `rotate` / `overlay` 实现，分层素材分别处理；
- 视频镜头与静态镜头统一时间线，转场用 `xfade`；
- 混音：对白 −16 LUFS 左右，BGM 压低 12–18 dB，音效按场景；
- 导出：MP4 + SRT/ASS + 封面 + 工程文件归档；
- 投稿包：成片、封面、简介、AI 标识说明、备案信息。

### 4.17 质量门禁（每集必过）

- [ ] 角色一致性：发型/瞳色/服装/饰品无跳变
- [ ] 构图与景别：无重复机位、无「PPT 平移」长段
- [ ] 手部/文字/道具：无明显崩坏
- [ ] 剧情连贯：场与场之间无跳跃
- [ ] 音频：无爆音、无空洞、对白清晰
- [ ] 字幕：无错字、无错位、专有名词统一
- [ ] 合规：AI 标识、备案信息、无低俗/暴力/迷信内容
- [ ] 时长与规格：6–8 分钟、16:9、24fps

### 4.18 算力与工时估算

| 项 | 单集 | 第一季（3–6 集） |
|---|---|---|
| 出图 | 100–180 张，1–2 h | 3–12 h |
| i2v | 5–10 条，0.5–2.5 h | 1.5–15 h |
| TTS | 50–100 句，10–20 min | 0.5–2 h |
| 人工 | 2–4 人日 | 6–24 人日 |
| 边际电费 | 几元 | 几十元 |

> 结论：算力不是瓶颈，**人的时间才是**。第一季 3 集，单人全职约 3–6 周；团队 2–3 人可压到 2–3 周。

### 4.19 与 ImageHub 的对接点

- 新增 `drama` 模块：项目/集/场景/镜头 CRUD、批量渲染、导出；
- 复用现有 GPU 仲裁与图像/TTS 互斥，不另起调度器；
- 新增 `/api/drama/*`：`project`、`episode`、`shot`、`render`、`batch`、`export`；
- 长任务队列 + 断点续跑 + 失败重试；状态写入 `drama_renders`；
- 鉴权与现有 API 一致（apikey / Bearer / 会话）；
- 前端可在现有单页新增「漫剧」tab（P4 之后再做，先用 API + 脚本跑通）；
- 不改 `jobs` / 图库；漫剧资产独立目录、独立表。

### 4.21 技术风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 角色漂移 | 前后镜头不像同一人 | 角色圣经 + 参考图 + 抽检 + Edit 局部修 |

## 5. 落地路线（推荐）

### 阶段 0：核实（1 周，0 成本）

1. B 站觉醒漫剧计划 2.0 当前是否仍开放、分成/保底档位、个人投稿的备案路径；
2. 属地广电对 AI 微短剧备案的主体要求（个人能否由平台代报）；
3. 番茄 IP 库当前可改编类型、分发范围、是否暂停新增；
4. 3 本候选小说的版权状态（自写/公版/授权）。

### 阶段 1：样片（3–4 周，低投入）

- 选公版或自写短篇，做 **3–5 集、每集 6–8 分钟** 的横屏样片；
- 跑通「故事圣经 → 分镜 → 出图 → 配音 → 剪辑 → 投稿」全链路；
- 目标不是爆款，是验证：单集工时、角色一致性、审核通过率、自然流数据（完播/追更/弹幕反馈）。

### 阶段 2：主体与量产（1–2 月）

- 样片数据达标后，注册公司或挂靠 MCN，办理资质与备案；
- 再考虑购买授权 IP 或继续原创；
- 按季规划（3–6 集/季），不要一开始铺 80 集。

### 不推荐

- 一开始双平台（竖屏/横屏两版，成本约 ×1.8）；
- 「拼书 + AI 洗稿」；
- 全片 i2v；
- 未核实政策就批量投入。

## 9. 一页版决策

- **做什么**：B 站原创横屏精品动态漫，第一季 3–6 集，每集 6–8 分钟。
- **IP 从哪来**：公版 / 自写 / 单独授权；「3 合 1」只提炼母题，不拼表达。
- **技术上怎么做**：动态漫为主 + 关键镜头 Wan2.2 i2v；角色圣经保证一致性；ImageHub 承担出图与 TTS。
- **先验证什么**：3–5 集样片的工时、一致性、过审率、自然流数据。
- **什么时候投钱**：样片数据达标后，再注册主体、办证、备案、买授权。
- **绝对不做**：番茄 IP 未授权改 B 站；拼书洗稿；未备案先上线。
